Explainer Engine

一条确定性的流水线，把 storyboard 编译成带旁白的概念讲解视频——屏幕上每个说法，都在画出第一帧之前带引用、按源码核对过。

{% include project-summary.html %}

是什么

Explainer Engine 把一份 YAML {% include glossary-term.html term="storyboard" %} 编译成 {% include glossary-term.html term="manim" %} 的带旁白场景。每个 beat 可以是一张图、一段带引用的代码标注，或者——最新的——一张会动的概念图：把带标签的节点摆在命名好的锚点上，连上力的边、一条路径，再让一个节点沿路径移动。整条链路一次跑完，中间没有模型： storyboard → 引用校验门 → 确定性代码生成 → Manim 渲染并合成旁白。这是私有、本地工具；对应的快照写在下面的「证据」里。

要解决的问题

讲解会和它所描述的代码慢慢脱节，而一段渲染出来的讲解，脱节得无声无息：视频照样播放，图照样好看，没有任何东西告诉你，屏幕上那个说法早在两次重构之前就对不上源码了。转述本来就容易在细节上出错，制作越精良反而越糟——一个包装得漂亮的说法，看起来比一个没核对过的说法更权威，可它不配。所以引擎真正要回答的，不是「怎么渲染一段讲解」，而是「一段渲染出来的讲解，要靠什么才能拒绝脱节」。

约束与关键决策

引用不上的说法，拒绝画。渲染之前，引用校验门会按固定 commit 从源仓库里读出被引用的行，核对所声称的证据是否真的在那里；还有一道 commit 诚实性检查：如果徽标上的 commit 和仓库 HEAD 对不上、或者工作区是脏的又没显式放行，构建就会失败。代价：写 storyboard 变慢了——每个说法都得配一条能解析的引用，一份跑得比源码还快、对不上引用的 storyboard 根本渲染不出来。

教学视图明确标出来，绝不冒充源码。屏幕上的内容始终标着 simplified（简化视图）——重新整理过的教学视图，绝不当成逐字源码来展示。那个琥珀色标签和 verified @ commit 徽标不是装饰，而是校验门的结论，被渲染进了画面。代价：每一帧都带着这套披露装置——有些像素花在了交代出处上，而不是花在好看上。

确定性代码生成，中间没有模型。同一份 storyboard 永远生成同一个场景，渲染可复现，输出上的任何差异都能追回输入上的差异。图示画布（diagram canvas）把关系变成动画，而不用手写场景代码——正因如此，能被讲清楚的是一个概念，而不只是一段代码清单，而且它仍然是可核对的。代价：storyboard 没写的东西就不存在；想要新的 beat 类型，得改引擎，不是改提示词。

一套渲染核心，两个使用方。引擎跑在一套共享、与 Qt 无关的渲染核心上——和桌面批量渲染 GUI 用的是同一套——所以这条渲染路径是经过统一测试的，而不是单次脚本。代价：核心的每次改动都有两个使用方要照顾，引擎不能走那种会把 GUI 卡死的捷径。

证据

私有快照 local tag diagram-canvas——没有可查看的公开源码。支撑这些说法的是产物本身：上面这段视频是引擎的真实输出，不是效果图。里面的五种力来自一份研究 wiki；屏幕上的徽标标注了「memory force」所核对的具体源码行与 commit，且渲染开始前引用校验门已通过。披露标记——simplified 标签、verified @ commit 徽标——每一帧都看得见。视频本身只能核对产物和这些可见标记；引用的私有源码行与校验门结果，目前无法由外部独立核对。若源码以后公开，外部读者可以自行核对引用行；当时的校验门结果仍需要公开运行证据。

下一步

目前没有承诺到里程碑的计划。方向由图示画布只答了一半的那个问题来定：一个概念有多少内容能做成动画讲出来，同时仍可按源码核对。仓库若变为公开可访问，再补源码链接。

它不是什么

  • 不是 LLM 视频生成器——代码生成是确定、可复现的。
  • 不是幻灯片——图示画布动的是关系，不是要点列表。
  • 不是逐字源码查看器——屏幕上的代码是带标记的简化视图，真实的行都给了引用。
  • 不是传递可信度的媒介——徽标给出的是校验门的结论，不是证据本身；真要核对说法的读者，需要的是链接，不是叙述。
